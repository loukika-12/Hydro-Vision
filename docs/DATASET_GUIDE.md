# HydroVision Dataset Guide

## Provenance

`data/raw/hydrovision_synthetic_dataset.csv` is a synthetic, simulated dataset created for development and demonstration. It is not official measured water data. Every row carries `data_type=synthetic_demo`. Do not describe its values as live measurements in reports or presentations.

- Coverage: monthly records, January 2019–December 2025
- Geography: six example locations in Telangana
- Rows: 504
- Intended use: database seeding, dashboard testing, ML pipeline development
- Original demo source: `data/raw/water_resources_demo.csv` remains available for legacy demo locations.

## Columns

| Column | Unit / format | Meaning |
|---|---|---|
| `date` | YYYY-MM-DD | Monthly record date |
| `location` | text | Example location |
| `state` | text | Telangana |
| `latitude`, `longitude` | decimal degrees | Approximate reference point, not official station coordinates |
| `rainfall_mm` | mm/month | Simulated rainfall |
| `temperature_c` | °C | Simulated monthly mean temperature |
| `humidity_pct` | % | Simulated relative humidity |
| `evaporation_mm_day` | mm/day | Simulated evaporation indicator |
| `groundwater_depth_m` | metres | Simulated depth to groundwater; higher values mean a deeper water table |
| `reservoir_storage_pct` | % | Simulated reservoir storage |
| `population_estimate` | people | Simulated population estimate |
| `water_demand_mld` | million litres/day | Simulated demand |
| `estimated_water_supply_mld` | million litres/day | Simulated supply |
| `water_availability_pct` | % | Simulated supply divided by demand × 100 |
| `scarcity_risk` | category | Rule-generated Low / Moderate / High / Critical label |
| `data_type` | text | Provenance marker, `synthetic_demo` |

## Database mapping

`database/seed.py` imports this file idempotently into SQLAlchemy's `water_data` table. It matches records by location and calendar month, because legacy demo dates are month-end while synthetic dates are month-start. It does not add a second record for a location/month already present.

The database maps fields as follows:

- `rainfall_mm` → `rainfall`
- `temperature_c` → `temperature`
- `humidity_pct` → `humidity`
- `evaporation_mm_day` → `evaporation`
- `groundwater_depth_m` → `groundwater_level`
- `reservoir_storage_pct` → `reservoir_storage`
- `population_estimate` → `population`
- `water_demand_mld` → `water_demand` after multiplying by 1,000 to match the approximate numeric scale of the legacy model input. This compatibility conversion is not a validated physical-unit calibration.
- `water_availability_pct` → `water_availability`

Existing environmental fields are preserved when a matching legacy row exists. If its availability target is missing, the importer fills the target from the synthetic dataset and marks the record `mixed_synthetic_target`. New imported rows are marked `synthetic_demo`; old rows are marked `legacy_demo`. The API returns this provenance, and the history table labels each row's source.

## Risk-label thresholds

The dataset uses the current project configuration thresholds:
- Low: availability ≥ 80
- Moderate: 60 ≤ availability < 80
- High: 40 ≤ availability < 60
- Critical: availability < 40

These are prototype thresholds in `config/risk_thresholds.json`, not official drought classifications or expert-validated criteria.

## Suggested ML evaluation

- Regression target: `water_availability_pct`
- Classification target: `scarcity_risk`
- Candidate features: rainfall, temperature, humidity, evaporation, groundwater depth, reservoir storage, population, water demand, plus date/lag/rolling features.
- Do not use `estimated_water_supply_mld` as a feature when predicting availability, because the target is calculated from supply and demand.
- Do not use `scarcity_risk` as a regression feature or `water_availability_pct` as a classification feature.
- Use a chronological split, not a random row split, for time-series validation.
- Because the values and labels are generated by formulas, strong metrics on this dataset do not demonstrate real-world predictive performance.

## Production and persistence notes

The app supports a `DATABASE_URL` connection through SQLAlchemy. A default SQLite database is suitable for local demonstration, but a typical Render web service filesystem is not a reliable persistent database across redeploys/restarts. Configure a managed PostgreSQL database and set `DATABASE_URL` in Render before relying on retained records. No PostgreSQL instance is currently attached to the Render workspace.

For research-grade results, replace or validate the synthetic data with documented measured records from trusted sources. Record source, station/location, measurement date, unit, missing-value handling, license, and update cadence.
